light-cljs

A ClojureScript compiler written in Rust.

Try the playground GitHub repository Documentation

light-cljs is a ClojureScript-to-JavaScript compiler written in Rust. It reads .cljs/.cljc source, resolves and analyzes it in Rust, and emits a single self-contained JavaScript expression that carries its own persistent-collection runtime. The same compiler powers a script runner, a REPL and an embedding API that execute the emitted JavaScript in an embedded QuickJS engine, so no Node, JVM or installed cljs.core is needed to run code.

Status: ClojureScript support is substantial but partial. Core special forms, macros, namespaces, persistent and sorted collections, lazy sequences, transducers, protocols, types, records, multimethods, atoms, exceptions and JavaScript interop work, and behavior is regularly compared against standard ClojureScript. It is not a drop-in replacement; the differences are below.

The playground runs the compiler itself in your browser, built for WebAssembly: edit a few namespaces, compile them at any optimization level, read the JavaScript and run it.

How it differs from ClojureScript

  • Numbers are always JavaScript Numbers, including at macro-expansion time. N/M literals and integral ratios become Numbers; a ratio such as 1/3 is rejected.
  • Libraries: only cljs.core (the supported subset), clojure.string, clojure.set, clojure.walk, clojure.edn and cljs.reader are bundled. There is no Google Closure Library, cljs.pprint, cljs.test, core.async or test.check; other namespaces are supplied as source.
  • JavaScript packages come from the host. A libspec such as ["react" :as r] reads the globalThis.lightCljsPackages registry, or, with --esm, becomes a static import for a bundler such as Vite or esbuild. The compiler does no package resolution and never reads node_modules.
  • Output is one JavaScript expression, or one ES module with --esm; there are no per-namespace modules. Source maps (v3) are supported at every optimization level.
  • Macros are written in .cljs/.cljc and run in the embedded QuickJS engine, not the JVM; .clj macro files are never loaded.
  • Optimization: the release mode, --optimize advanced, is light-cljs's own and still being built. Today (js/console.log (+ 1 2)) compiles to about 150 bytes, a small record and protocol program to about 6 KB, and a program that prints keeps the printer (about 21 KB).
  • The embedded engine used by the script runner and REPL provides ECMAScript only: no DOM, Node APIs, filesystem or network unless the host supplies them. Compiled output runs wherever JavaScript does.

The README's known boundaries keep this list current, and the compiler reference documents supported forms, runtime semantics and the deliberate differences in detail.
